## Shared credit allowance

The application uses one persistent Upstash Redis hash through its HTTPS REST API. Both photo endpoints and every app instance use the fixed key `sangeetfit:live-budget:v1`. Redis executes the conditional reservation atomically using [EVAL](https://upstash.com/docs/redis/commands/scripting/eval). No Redis package is needed; the store contains only four aggregate integers, never photos, participants, invite codes or provider URLs.

Persistent storage setup, the 10-unit initialization and one mock Preview deployment are authorized and recorded; further deployment and live activation still need separate approval. Do not use an expiring trial database for judging. Configure server-only `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN` in the same environments as the provider key, or use the Vercel-managed integration's existing `KV_REST_API_URL` and `KV_REST_API_TOKEN` pair. The connected store supplies the sensitive KV pair in Preview and Production, so copying its secrets into aliases is unnecessary. If either explicit Upstash field is nonempty, only that family is used; an incomplete/invalid explicit pair fails closed instead of borrowing a KV credential. The read-only KV token cannot reserve units and is never substituted. The URL must be an HTTPS `*.upstash.io` root with no credentials, port override, path or query. Do not put secrets in command arguments or print environment files.
