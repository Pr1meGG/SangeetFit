# SangeetFit redesign v2

## Outcome and scope

On local branch `codex/redesign-v2`, adapt the visual hierarchy and navigation patterns observed at https://glowstack.in/ to SangeetFit's existing styling tools. Preserve the uncommitted `experiments` work, existing brand mark, API behavior, photo permissions, explicit generation and session privacy. No new dependency, live generation, deployment or publication is required.

## Reference and design decision

REA's CDP page inspection, screenshot and static bundle analysis on 26 October 2026 found a floating pill header, dark plum/gold split hero, serif display type, light feature sections, numbered walkthrough and native FAQ disclosure. Use these patterns with original SangeetFit copy, its local Bodoni font and its existing AI outfit concepts. Do not reuse Glowstack's code, logo, photography, videos or business claims.

An exact marketing-site clone would obscure the working styling tools; a header-only change would leave the experience inconsistent. The selected approach combines the pill navigation and editorial home with direct access to the existing wardrobe, shortlist, comparison and five-event planner. Library and fitting tools retain their readable light surfaces.

## Files and integration

1. `src/components/Navbar.tsx`: desktop navigation, current location, count, plan CTA, truthful mode indicator and accessible phone disclosure. Parent callbacks preserve the home session; library uses existing links. Escape, outside click, selection and desktop resize dismiss the disclosure.
2. `src/app/page.tsx`: wire shared navigation to existing state; support `view=plan`; focus/scroll committed section targets. Keep existing two-line headline, occasion flow, bottom bar, catalogue, upload, consent, results and print behavior. Add an original feature overview, walkthrough, FAQs and footer.
3. `src/app/globals.css`: replace incumbent navbar/hero rules and add scoped redesign sections using shared tokens. Maintain reduced motion, keyboard focus, touch targets and 320px layout.
4. `src/app/library/page.tsx`: declare the collection navigation state; retain existing search/filter contracts.
5. `tests/redesign-v2.browser.test.mjs`: navigation/session, mobile disclosure, anchors, FAQ, deep link and zero-generation regression checks. Existing runner discovers the suite automatically.
6. `docs/research/2026-10-26-glowstack-design-teardown.md` and workflow state files: retain evidence, scope and actual verification outcomes.

Navbar and its new browser test have one builder; primary owns integration, styling, home, library and documentation. Read-only scout maps callers/contracts. Independent reviewers inspect the completed change.

## Acceptance and verification

- Desktop and phone navigation reaches real app surfaces. Home navigation preserves photos, clothes, shortlist, plan and results; leaving the route retains the existing confirmation.
- Menu and FAQ work with keyboard; anchor focus clears the sticky header. No horizontal overflow at 320/390/768/1024/1440/1920.
- Keep the primary task first after Skip to content; maintain the intended two-line hero and collection filters.
- Navigation, FAQs, browsing and plan changes submit zero `/api/skin` or `/api/vto` requests. Existing explicit generation contracts remain intact.
- Run `TEST_PORT=3551 npm run verify` for contracts, TypeScript, lint, mock build and browser suites; inspect actual exit status. Real Redis may be skipped when not configured.
- Inspect phone/desktop renders and errors on an isolated mock preview; run `git diff --check`. Review the task's delta against the pre-edit local snapshot so pre-existing changes are not attributed to this work.

## Risks and limits

The starting checkout has substantial uncommitted release/UI work. Preserve all of it and keep this checkpoint local. Session state is page-owned; use callbacks for same-page navigation. Dark colours are confined to navigation/home presentation so form, camera and result contrast are not globally inverted. New screenshots show mock browsing and existing AI concepts, not new live quality evidence. Phone emulation does not verify physical-device behavior.
