## 0:00–0:20 — The decision

**Screen:** “Five moments. One wardrobe.” home → open the empty five-event board and show its occasion slots and labelled inspiration options, without uploading a person photo.

**Voiceover:** “A wedding has five different moments, but I don’t need five new outfits. I can plan what I already own, rewear a favourite, and use inspiration only where I need another idea.”

The board contains AI-generated outfit concepts as clearly labelled candidates. Show their unreviewed labels; planning is not a personal try-on. A personal generated result still needs a suitable person photo.

## 0:20–0:50 — Your clothes and explainable recommendations

**Screen:** Add two owned outfits → confirm each garment photo, reference category, main colour, style and occasion tags → assign one across two functions on the board → show the recommendation reason.

**Voiceover:** “I’m adding my own garment. I confirm these details myself; we aren’t pretending to analyse the photo for style. Recommendations use the occasion, my style preference and chosen colour. Every reason states the tags it actually matches.”

Show a real reason. Do not use skin-harmony percentages, unsupported comfort/sizing claims or “perfect match” language. Optional skin analysis is a separate feature and can be skipped in the core demo.

## 0:50–1:25 — Personal try-on

**Screen:** Open outfit → person-photo consent → review front-facing full-body photo → explicit Generate.

**Voiceover:** “Adding clothes does not start an AI task. After I consent and press Generate, the app sends my person photo and this garment reference to YouCam Cloth V4, then polls for a result. My face selfie, if I use optional skin analysis, is a separate input.”

Show the actual loading/result state. If using authorized live footage, keep “Live AI preview” visible and inspect identity/garment details. If using mock footage, say: “This segment is a mock reference preview, not a generated image of me.” Do not switch modes invisibly.

Prior approved tasks succeeded for one sample-person/maroon-lehenga pair; that is limited pipeline evidence. Uploaded-garment quality and broad face retention are not established merely by that history.

## 1:25–2:05 — Compare and choose

**Screen:** Generate a second authorized look with the same person photo, or show a previously recorded genuine result from the same source → two session results → original/result toggle → zoom → Choose look → save/open image.

**Voiceover:** “Now I can compare the two outfits I own and choose one without changing clothes repeatedly. Comparing these existing results submits no extra generation tasks. The app labels which photo and mode produced each look.”

If sources differ, show the warning; do not imply fair same-source comparison. Explain session-only retention and provider-link expiry. Demonstrate only save/share behaviour actually tested on the recording device. Catalogue outfit links share selection, not private result photos; own uploads do not create public share links.

## 2:05–2:30 — Integration and honest scope

**Screen:** final choice, concise integration/limitations card.

**Voiceover:** “Built with Next.js, TypeScript and YouCam, SangeetFit connects recommendations with a personal preview. AI can alter details, so this is a visual aid, not a sizing or face-preservation guarantee. Our live-quality scorecard and test coverage are reported honestly.”

Show only recorded benchmark values/sample sizes. If still pending, label them pending. The owned-clothes decision is the main story; the model-led collection is optional inspiration until its exact references pass live review. Show **View at seller** only if an actual exact-item listing and image permission have been verified. Otherwise omit commerce footage; no seller collection is currently verified. Session clothes and results disappear on refresh; do not imply a permanent wardrobe. Top-and-bottom combinations are future work.
